# Учебная задача: модель исправляет код и проверяет себя

В `invoice.py` намеренно ошибочная функция; исходные тесты **должны падать**. Это отдельный демонстрационный проект, не часть unit tests инструментов развёртывания.

Сделать временную копию, чтобы сохранить исходное задание:

```bash
cp -R examples/demo-project /tmp/deepseek-webinar-demo
cd /tmp/deepseek-webinar-demo
python3 -m unittest -v
```

Если каталог назначения уже существует, выбрать новый, не затирать предыдущие результаты. Показать ошибки зрителям. Запустить настроенный launcher free-code в этом каталоге и дать задание:

> Прочитай invoice.py и test_invoice.py. Исправь только invoice.py, тесты не меняй. Функция считает общую стоимость в целых центах, учитывая количество. Цена и количество — неотрицательные int, bool недопустим. Для отрицательных значений ValueError, для другого типа TypeError. Выполни тесты и объясни причину ошибки. Не устанавливай зависимости и не обращайся к сети.

Разрешить клиенту только необходимые чтение/редактирование файла и запуск `python3 -m unittest -v` в учебном каталоге. После работы **самостоятельно** повторить тесты и сравнить invoice.py с оригиналом. Проверить, что test_invoice.py не изменён.

Успех: все пять тестов проходят, модель действительно вызывала инструменты, файл изменён, ответ объясняет исправление. Это проверяемая демонстрация короткой задачи, не общая оценка модели. На первоначальном GPU-стенде был проверен Read; именно эта coding-задача ещё требует репетиции моделью.
