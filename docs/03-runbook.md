# От чистого GPU-узла до ответа модели

> Это сохранённый FP8/Docker-рецепт. Он не является текущим EXL3 installer и не прошёл чистую GPU-репетицию. Переносимый маршрут — [здесь](08-portable-deployment.md).

Все команды сервера — Bash, из корня скопированного каталога `ds4f_nolimit_webinar`. Требуется выделенный узел по [спецификации](02-server.md) с уже работающим Docker/NVIDIA runtime. Установку драйвера и перезапуск Docker на занятой машине в этот маршрут не включаем. Если runtime отсутствует, выбери готовый GPU-шаблон или установи его по [официальной инструкции NVIDIA](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html) и повтори проверки.

## 1. Подготовить каталог и образ — сервер

Скопируй материалы на сервер через `scp -r -P SSH_PORT ds4f_nolimit_webinar SSH_USER@SSH_HOST:~/`. Подставь свои реквизиты; приватный ключ копировать на сервер не нужно. Далее:

```bash
cd ~/ds4f_nolimit_webinar
# Подставить существующий доступный каталог на большом устойчивом томе:
export DS41_ROOT=/srv/ds41
source scripts/config.sh
mkdir -p "$DS41_ROOT/model" "$DS41_ROOT/cache" "$DS41_ROOT/reports"
df -h "$DS41_ROOT"
docker pull "$SGLANG_IMAGE"
docker run --rm --gpus all --entrypoint nvidia-smi "$SGLANG_IMAGE"
docker run --rm --entrypoint python3 "$SGLANG_IMAGE" -m sglang.launch_server --help > "$DS41_ROOT/reports/sglang-help.txt"
docker run --rm --entrypoint python3 "$SGLANG_IMAGE" -m pip freeze > "$DS41_ROOT/reports/pip-freeze.txt"
docker image inspect "$SGLANG_IMAGE" --format '{{json .RepoDigests}}' > "$DS41_ROOT/reports/image-digests.json"
```

Если `mkdir` отказал в доступе, укажи каталог, выданный провайдером; не меняй права общего тома рекурсивно. Контейнер обычно создаёт файлы от root: управление ими может требовать прав администратора на выделенном узле.

Убедись, что внутри образа видны все 8 H100. В сохранённом `--help` должны быть параметры из `scripts/serve.sh`; отсутствие любого из них блокирует продолжение. Digest был проверен по Docker Hub, но образ здесь ещё не запускали. Не заменяй его на `latest`, чтобы скрыть несовместимость: сначала зафиксируй и испытай новую версию.

## 2. Скачать и проверить веса — сервер

Публичная модель обычно скачивается без токена. Ничего секретного в команды не вставляй. При HTTP 401/403 сначала проверь доступность репозитория и условия доступа на HF; ошибка не означает автоматически, что нужен платный аккаунт.

```bash
docker run --rm \
  -v "$DS41_ROOT:/data" \
  -v "$PWD/scripts:/scripts:ro" \
  -e MODEL_REPO -e MODEL_REVISION -e HF_HOME=/data/cache/huggingface \
  --entrypoint python3 "$SGLANG_IMAGE" /scripts/download.py
python3 scripts/verify-weights.py "$DS41_ROOT/model" > "$DS41_ROOT/reports/weights-check.txt"
tail -n 1 "$DS41_ROOT/reports/weights-check.txt"
```

Ожидается `PASS: 48 safetensors verified`. Это полное чтение примерно 510 GB и отдельный заметный этап. При прерывании скачивания повтори команду с тем же `local_dir`: библиотека использует метаданные загрузки. Не начинай запуск при несовпадении размера или SHA256.

Манифест проверяет все safetensors; конфигурационные файлы загружаются из того же закреплённого snapshot, но их хеши этим скриптом не проверяются. `--trust-remote-code` разрешает исполнение кода из checkpoint, если загрузчик его запросит; ревизия закреплена, отдельный аудит кода не проведён.

## 3. Запустить модель — сервер

```bash
bash scripts/serve.sh
docker logs --tail 100 -f ds41-webinar
```

`Ctrl-C` завершит просмотр логов, контейнер продолжит работать. Начальная конфигурация: TP8/EP8, контекст 262144, не более 8 одновременных запросов. Это стартовые настройки для репетиции, а не обещание ёмкости под восемь полных контекстов. Доля статической памяти 0.80 — консервативная начальная настройка, отдельно не измерена. Engram размещается в RAM; JIT-кэши сохраняются на томе. DSpark пока не включён: его профилирование — отдельная оптимизация.

API слушает все интерфейсы **внутри** контейнера, но Docker публикует его только на `127.0.0.1` хоста. Публичный порт 30000 открывать не требуется. SSH-туннель даёт доступ владельцу SSH-ключа; другие локальные пользователи сервера также могут обратиться к loopback API. Поэтому нужен выделенный доверенный узел.

Первый успешный запуск прежней установки из исходников занимал около 14 минут. Для нового образа время неизвестно: ориентируйся на логи и запросы, а не на таймер. Проверка готовности:

```bash
curl --fail --show-error --max-time 30 http://127.0.0.1:30000/health
curl --fail --show-error --max-time 30 http://127.0.0.1:30000/v1/models
```

При OOM или ошибке ядра перейди к [диагностике](05-troubleshooting.md). Автоматические рестарты на этапе отладки отключены, чтобы сохранить понятную причину остановки.

## 4. Подключиться с ноутбука

В отдельном терминале, заменив `SSH_PORT`, `SSH_USER`, `SSH_HOST`:

```bash
ssh -N -T -p SSH_PORT \
  -o ExitOnForwardFailure=yes \
  -o ServerAliveInterval=30 -o ServerAliveCountMax=3 \
  -L 127.0.0.1:18080:127.0.0.1:30000 SSH_USER@SSH_HOST
```

Терминал должен оставаться открытым. Из второго терминала ноутбука, в корне материалов:

```bash
python3 scripts/smoke.py
curl --fail-with-body --show-error --max-time 600 \
  http://127.0.0.1:18080/v1/chat/completions \
  -H 'Content-Type: application/json' --data-binary @examples/chat.json
```

`smoke.py` требует правильный ID модели, фактический ответ `323` и завершение `stop`. Тест намеренно строгий: если модель добавила пояснение, исследуй сырой JSON, а не объявляй сервер неисправным. `finish_reason=length` означает исчерпание лимита ответа; это не успешное завершение задачи. Для быстрого теста в запросе выбран `reasoning_effort=low`; сильное рассуждение проверяй отдельным запросом с большим бюджетом ответа.

Проверка потокового ответа:

```bash
python3 - <<'PY'
import json
from pathlib import Path
p=json.loads(Path('examples/chat.json').read_text())
p['stream']=True
Path('/tmp/ds41-stream.json').write_text(json.dumps(p))
PY
curl -N --fail-with-body --show-error --max-time 600 \
  http://127.0.0.1:18080/v1/chat/completions \
  -H 'Content-Type: application/json' --data-binary @/tmp/ds41-stream.json
```

Убедись, что поток заканчивается `data: [DONE]`, итоговый текст собран из `delta.content`, а reasoning при его наличии — из `delta.reasoning_content`.

## 5. Подключить клиент

Для клиента с поддержкой OpenAI-совместимого API:

- Base URL: `http://127.0.0.1:18080/v1`.
- Model: `deepseek-v4.1-flash`.
- Реальный API-ключ в этой схеме не используется; если клиент требует поле, допустима несекретная заглушка `local-only`.
- Для первой проверки: один запрос, контекст до 262144, ответ до 2048 токенов, `reasoning_effort=low`, если клиент поддерживает поле.

Если клиент работает в собственном контейнере, его `127.0.0.1` указывает на него самого. Эти адреса предназначены для клиента, запущенного непосредственно на ноутбуке.

В посте использован клиент free-code. Это дополнительная глава: для уже установленной и проверенной сборки исторически работал native Anthropic API SGLang с `ANTHROPIC_BASE_URL=http://127.0.0.1:18080` (без `/v1`) и `ANTHROPIC_MODEL=deepseek-v4.1-flash`. Установку и совместимость конкретной публичной сборки free-code с новым образом нужно отдельно проверить; этот комплект не выдаёт её за готовую часть маршрута. Для основного вебинара достаточно работающих HTTP-запросов.

Для показа агентского сценария используй отдельный учебный каталог с искусственными данными. Приёмка — клиент прочитал контрольный файл через инструмент и вернул его содержимое. Обычный ответ в чате не доказывает работу tool calls.

## 6. Остановить и возобновить — сервер

Влияние: генерация и все клиенты этого демонстрационного контейнера станут недоступны; веса и кэши останутся. Возобновление — `docker start`.

```bash
docker stop -t 120 ds41-webinar
docker start ds41-webinar
```

После старта повтори `smoke.py` с ноутбука. После успешной репетиции можно включить восстановление контейнера при перезапуске Docker:

```bash
docker update --restart unless-stopped ds41-webinar
```

Для изменения параметров запуска: сначала сохрани нужные логи, останови контейнер, удали **только его** командой `docker rm ds41-webinar`, исправь `scripts/serve.sh` и запусти заново. Это прервёт текущие запросы; bind-mounted данные сохраняются. Для отката сохрани предыдущую версию скрипта и верни её перед повторным запуском.

После записи останови контейнер и туннель (`Ctrl-C` в его терминале). Остановка контейнера не прекращает аренду узла. Заверши аренду в панели провайдера, предварительно проверив сохранность нужных материалов и политику удаления тома. Удаление тома — отдельное необратимое действие.
