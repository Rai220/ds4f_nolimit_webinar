# EXL3 на Vast.ai: фактическое развёртывание 2026-09-22

> Состояние после работ: 2026-09-22 сервер остановлен. Ниже история успешного запуска, а не заявление о доступности сейчас. Адрес, порты и цена этой аренды в комплект не входят.

Модель **dealignai/DeepSeek-V4.1-Flash-UNCENSORED-EXL3-2.9bpw** запущена на **2×H200**. Проверены законченная генерация, SSE с `[DONE]` и цикл function call → чтение контрольного файла клиентом → ответ модели. Шаблонный Qwen остановлен, его автозапуск отключён по поручению владельца.

## Подключение с ноутбука

```bash
ssh -NT -p SSH_PORT user@host \
  -o ExitOnForwardFailure=yes -o ServerAliveInterval=15 \
  -L 127.0.0.1:8080:127.0.0.1:18080
```

Адрес и порт берутся из панели аренды. Держать эту команду открытой. Если локальный порт 8080 уже занят работающим туннелем, второй запуск не нужен. На сервере порт 8080 принадлежит Jupyter, поэтому назначение туннеля — **18080**.

- OpenAI base URL: `http://127.0.0.1:8080/v1`.
- Model ID: `deepseek-v4.1-flash`.
- API слушает только loopback; доступ обеспечивает SSH, отдельного API-ключа нет.
- Контекст 65536 токена, один одновременно исполняемый запрос, eager mode.

```bash
curl http://127.0.0.1:8080/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"deepseek-v4.1-flash","messages":[{"role":"user","content":"Сколько будет 17 * 19? Ответь только числом."}],"temperature":0,"max_tokens":64,"chat_template_kwargs":{"enable_thinking":false}}'

python3 deploy/smoke-exl3.py http://127.0.0.1:8080
```

Тест инструмента сам создаёт учебный файл и выполняет только заранее определённое чтение. Модель возвращает вызов функции, исполняет её клиент. Это не проверка полноценного coding harness.

## Управление на сервере

```bash
supervisorctl status ds41-exl3
supervisorctl restart ds41-exl3
supervisorctl stop ds41-exl3
tail -n 80 /workspace/ds41-exl3/logs/server.log
curl -f http://127.0.0.1:18080/health
```

Конфигурация — `/etc/supervisor/conf.d/ds41-exl3.conf`, команда — `/workspace/ds41-exl3/scripts/serve.sh`. Supervisor обеспечивает автозапуск при своём старте и перезапуск при неожиданном выходе. API готов только после `Application startup complete` и реального запроса, статус Supervisor RUNNING этого не гарантирует.

## Найденные несовместимости

1. В vLLM 0.30 пакет переименован из `deepseek_v4_1` в `deepseek_v41`; overlay адаптирован к новому пути и NVIDIA-подклассу Engram.
2. EXL3-ядра разделяют per-device locks. Параллельные attention CUDA streams вызывали зависание при mixed warmup. В NVIDIA model установлено `aux_stream_list=None` по авторскому исправлению. Одна переменная `DSV41_EXL3_SERIAL_STREAMS=1` без этого patch недостаточна.
3. NCCL NVLS multicast на этом контейнере возвращал CUDA 401. `NCCL_NVLS_ENABLE=0` устранил сбой; обычный P2P/IPC по NVLink используется.
4. FlashInfer all-reduce требовал отдельной тяжёлой JIT-сборки. Для первого запуска отключены FlashInfer/symmetric/custom all-reduce; используется PYNCCL. Это не утверждение об оптимальной скорости.
5. Дополнительные fat-grouped ядра не установлены; `EXL3_FAT_GROUPED=0`. Работают базовые EXL3 GEMM и fused MoE, их синтетические GPU-тесты прошли.

Первый успешный запуск исправленного runtime: процесс 12:52 UTC, готовность API 12:54:31 UTC. Арифметическая проверка с ноутбука: 18 входных и 2 выходных токена, 1,26 с вместе с запросом списка моделей. Это функциональный тест, не бенчмарк. Большой контекст, конкурентная нагрузка, качество reasoning, картинки и скорость coding harness ещё не проверены.

## Встроенный Model UI

В Vast.ai открыть **Model UI → Launch Application**. Внешний адрес и mapped-порт брать из панели текущего узла. Ссылка из панели передаёт штатную авторизацию Vast. Запрос к внешнему UI без авторизации отвечает 401 — это ожидаемо.

Схема: Caddy `7860` → Model UI `127.0.0.1:17860` → vLLM `127.0.0.1:18080`. Штатные Caddy и tunnel_manager сохранены. Авторизация не отключалась. Quick Tunnel проверен с авторизацией; его адрес может меняться при перезапуске.

Изменения воспроизводит [configure-model-ui.py](../deploy/configure-model-ui.py): backend и model ID задаются в `/opt/supervisor-scripts/model-ui.sh` после загрузки окружения, показывается вкладка Chat. В `/opt/model-ui/app.js` добавлена поддержка `delta.reasoning` наряду с `reasoning_content`. В HTML верхний предел ответа уменьшен до 4096 при текущем контексте 65536; история и запрос тоже занимают контекст. По умолчанию ответ ограничен 2048 токенами.

После применения: `supervisorctl restart model-ui`. Уже открытый браузер обновить. Проверены HTML с нужной моделью, выдача исправленного JS, `/api/models`, потоковый запрос через `/api/chat/completions`: ответ `323`, непустой reasoning, `finish_reason=stop`, `[DONE]`. Проверены Caddy и authenticated Quick Tunnel; визуальный браузерный тест отдельно не выполнялся.

Если SSH-прокси Vast разрывает соединения, прямой адрес берётся из карты портов панели. Ключ хоста сверять с уже известным ключом того же узла. Проверку ключа хоста не отключать. Порт этой аренды на новый узел не переносить.


## free-code на Mac

Проверена сборка free-code 2.1.119 из каталога `free_code/cli` (underscore). Исходники и бинарник не менялись. Отдельный launcher выбирает свой профиль, адрес `http://127.0.0.1:18081` и модель `deepseek-v4.1-flash`. Это native **Anthropic Messages API vLLM**, отдельный переходник не нужен. Переменная `CLAUDE_CODE_USE_OPENAI` в этом форке включает Codex OAuth и для этого подключения не подходит.

Контекст сервера и клиента увеличен до **65536** для системного промпта, инструментов и истории; предел ответа клиента **8192**. Effort — **high**: DeepSeek V4.1 не принимает `medium`. Полное заполнение контекста отдельно не проверялось.

Туннель `127.0.0.1:18081` → сервер `127.0.0.1:18080` держит пользовательский менеджер после сверки SSH-адреса и ключа хоста. API получает несекретную заглушку, отдельные платные API/OAuth не используются.

```bash
curl http://127.0.0.1:18081/v1/models
```

Локальные API-логи и их выгрузка в S3 выключены для этого профиля. Проверка скомпилированного клиента: вызов `Read` учебного файла → результат инструмента → правильный финальный ответ, 2 turns, exit 0, permission denials нет.


## Если файловая система когда-либо сохранена

Владелец отключил диск: для текущего продолжения нужен [чистый запуск](11-live-cold-start.md). Следующий абзац применим только к иной ситуации с сохранённой файловой системой.

После включения такого узла проверить актуальные IP, SSH и mapped ports в панели, сохранность `/workspace/ds41-exl3`, supervisor и `/health`. Если файловая система сохранена, не повторять installer/download: воспользоваться установленным сервисом. Туннель поднимать заново по адресу из панели, с проверкой host key. Затем проверить `/v1/models` через local 18081 и реальный запрос. Если адрес или ключ хоста изменились, исправить конфигурацию по данным нового узла; проверку host key не отключать.
