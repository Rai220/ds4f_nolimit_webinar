# Диагностика

> Этот документ относится к исходному FP8/Docker-маршруту. Полный каталог найденных ошибок — [новая диагностика](09-lessons-and-errors.md). Переносимый маршрут — [здесь](08-portable-deployment.md).

Начинай с `docker logs --tail 200 ds41-webinar`, `docker inspect ds41-webinar --format '{{json .State}}'`, `nvidia-smi`, `free -h` и свободного места на томе. Не публикуй логи без просмотра содержимого.

| Симптом | Что проверить и сделать |
|---|---|
| Docker не видит GPU | Сравнить `nvidia-smi` на хосте и внутри образа. Проверить NVIDIA runtime и драйвер по инструкции провайдера |
| Неизвестная архитектура / аргумент | Сверить digest, model revision и `--help`. Обычная установка `pip install sglang` не подтверждает поддержку V4.1 |
| `ninja` отсутствует | Проверить `command -v ninja` внутри образа. Это проблема состава окружения; исправленный образ закрепить новым digest |
| `crt/host_config.h` не найден | Ошибка toolkit при JIT. Для установки без Docker ранее потребовались CUDA CRT и libnvvm; не переносить пути той машины в новый образ |
| Ошибки FlashInfer / CUDA | Сохранить первую ошибку сборки и версии. Не удалять все кэши; при проверке нового окружения использовать отдельный каталог кэша |
| Процесс завершился с 137 | Проверить `.State.OOMKilled`, лимит RAM/cgroup и системный журнал, если доступен. Код 137 сам по себе не доказывает OOM |
| CUDA out of memory | Проверить свободную VRAM и процессы; на выделенном стенде уменьшить сначала число запросов/размер CUDA graph, затем контекст. Повторить приёмку |
| Ошибка формы MoE | Сверить TP8/EP8 и точную модель, не смешивать V4/V4.1 и квантования |
| `/health` ещё не отвечает | Проверить, продолжаются ли загрузка и JIT. Не перезапускать многократно исправно загружающийся процесс |
| `/health` успешен, генерация не проходит | Проверить сырой ответ, `finish_reason`, бюджет reasoning и логи. Health не является проверкой генерации |
| `<think>` в итоговом тексте | Проверить явный `reasoning_effort` в запросе и `--reasoning-parser deepseek-v41` |
| Tool calls показаны текстом | Проверить `--tool-call-parser deepseekv41`, формат запроса и поддержку инструментов клиентом |
| С ноутбука connection refused | Проверить SSH-туннель, занятость 18080 и ответ API непосредственно на сервере |
| После пересоздания узла пропали веса | Проверить, был ли том persistent и подключён ли он по прежнему пути. Не начинать новую загрузку до инвентаризации томов |

Источник особенностей модели: [карточка](https://huggingface.co/dealignai/DeepSeek-V4.1-Flash-UNCENSORED-FP8) и внутренний опыт установки от 2026-09-14. Таблица задаёт направления проверки, а не диагноз конкретного нового узла.

Операции перезапуска прерывают клиентов стенда. Меняй по одному параметру, сохраняй предыдущую конфигурацию и повторяй реальный запрос после каждого исправления.
