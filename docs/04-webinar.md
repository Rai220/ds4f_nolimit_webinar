# Вебинар: с пустого GPU-сервера до собственного DeepSeek

Длительность сейчас не задаётся. Приоритет — воспроизводимый запуск с пустого диска и материалы, по которым другой человек сможет повторить установку. Старый сервер остановлен, диск отключён; сохранённые веса и окружение не предполагаются.

## Целевое демо (решение 2026-09-23)

**dealignai DeepSeek V4.1 Flash UNCENSORED FP8** — 763,2 млрд параметров (из них 196,6 млрд — таблицы Engram), около 16 млрд активно на токен; исходная точность модели (FP8 + эксперты MXFP4) на **4×H100 80GB**, штатный vLLM 0.30.0: TP=4 + EP, CUDA graphs, DSpark k=3, окно 65536, до 4 запросов, без vision. Профиль — [profiles/fp8-vllm-h100-4x80.env.example](../profiles/fp8-vllm-h100-4x80.env.example).

Эталон измерен на ноутбуке Cloud.ru с 4×H100: 206 токенов/с в один поток, 644 в сумме при 4, smoke 3 PASS ([docs/13](13-speed.md#fp8fp4-версия-на-том-же-4h100--быстрее-exl3)). На 2×H200 FP8 не помещается; тогда запасной вариант — EXL3 2.9 bpw ([чистая установка](11-live-cold-start.md) + быстрый режим). Менять формат или GPU впервые в прямом эфире не следует: такой вариант сначала проходит отдельную репетицию.

**Сервер эфира — новая аренда на Vast.** Что проверить в предложении до оплаты:

| Параметр | Требование | Откуда |
|---|---|---|
| GPU | 4×H100 SXM 80GB или 4×H200, Hopper или новее | Эталон: 73,4 GiB весов на карту из 79,2. Attention идёт через sparse FlashMLA, он рассчитан на Hopper+ |
| Связь GPU | NVLink | Эталон — NV18. H100 PCIe с TP=4 не проверяли |
| CUDA драйвера | 13.0 и выше | Torch `2.13.0+cu130`. На прошлом Vast H200: driver 590.48.01, CUDA 13.1 |
| RAM инстанса | от 256 GB | 189 GiB таблиц Engram vLLM держит в pinned RAM. На Vast RAM делится между GPU хоста: при 4 из 8 карт выходит примерно половина |
| Диск | от 700 GB, локальный | 510 GB весов + venv + кэши + запас. Destroy/recycle стирает диск, stop/start сохраняет |
| Сеть | Высокий `inet_down` | 510 GB по 1 Гбит/с — минимум около 68 минут; на эталоне было около 900 МБ/с, 9,5 минуты |
| Шаблон | Чистый CUDA-образ с SSH | Шаблон с моделью может сам занять GPU (на прошлом Vast SGLang стартовал Qwen). Модель ставится в свой venv, образ ничего не должен запускать на GPU |

После входа: фактические GPU проверять через `nvidia-smi` и `ops/inspect.sh`, а не по названию шаблона (прошлый раз заказывали B200, пришли H200). Прочитать `/etc/vast-agents-guide.md`; не останавливать caddy, portal и tunnel_manager; порт 8080 занят Jupyter, API ставится на 18080. Репетицию делать на предложении того же типа, что в эфире.

Холодный запуск FP8 и замер скорости — по скилу [skills/ds4-fp8-vllm](../skills/ds4-fp8-vllm/SKILL.md): готовый конфиг, установка runtime и согласованного CUDA toolkit, веса с SHA256, `serve.sh`, фиксированный `bench.sh`. Runtime и веса независимы, их ставят параллельно.

Скил прогнан с пустого диска 2026-09-24 на ноутбуке Cloud.ru с 8×H100: установка runtime 11 минут, скачивание 11 минут 48 секунд, SHA256 6 минут, первый старт 295 секунд, smoke 3 PASS. На всех 8 картах (TP=8, 32 запроса, окно 1048576 проверено до 1 033 152 токенов) — 201–214 токенов/с в один поток и 2697 в сумме при 32; на 4 картах — 199 и 641 при 4 ([отчёты](../reports/2026-09-24/fp8/)). Если в эфире 8 GPU, брать 8-GPU профиль скила. По пути найдены две ошибки старого варианта этих команд: без согласованного toolkit падает JIT DeepGEMM и FlashInfer ([каталог ошибок](09-lessons-and-errors.md)).

## Что зритель должен получить

- Увидеть, как выбрать и проверить сервер, а не доверять имени шаблона.
- Скачать фиксированную модель и отдельные Engram-таблицы, проверить целостность.
- Получить OpenAI-compatible API и чат в браузере.
- Подключить агентский клиент и увидеть tool call → исполнение → ответ.
- Исправить учебный код и проверить результат тестами.
- Забрать репозиторий с теми же командами и адаптировать профиль к своему серверу.

## До эфира: готовим инструкции, а не скрытый прогретый стенд

1. Один раз пройти [полный холодный запуск](11-live-cold-start.md) на чистом временном сервере: скрипты после обобщения ещё не проверены целиком с нуля.
2. Записать фактические длительности download/install/SHA/JIT, версии базового образа и peak RAM/VRAM. Найденные исправления включить в публичный комплект.
3. Проверить UI, клиент, tool round trip и учебную задачу. Проверить, что повторная установка не требует незаписанных ручных правок.
4. Выключить/освободить временный стенд и ненужный диск после репетиции по решению владельца. Постоянное платное хранение для сценария не требуется.
5. Зафиксировать выпуск кода (commit/tag после создания репозитория). Проверить публичный архив; заранее подготовить на ноутбуке SSH-клиент и выбранную сборку free-code. Не показывать токены, SSH-ключи или приватные настройки.
6. На репетиции включить быстрый режим на **том же типе железа**, что будет в эфире, и снять замер `ops/bench-decode.py` ([docs/13](13-speed.md)). На 4×H100 baseline в eager был в 5 раз медленнее (11 против 58 токенов/с); без графов и DSpark демонстрация выглядит медленнее, чем модель может. Если в эфире будет другое железо, чем на репетиции, выбрать схему по таблице в docs/13 и заранее держать baseline-профиль для отката.
7. Для самого эфира начать с пустого каталога весов и кэшей на новом сервере. Если что-то предустановлено провайдером, прямо назвать это: CUDA toolkit, Python, uv и исходный SGLang-шаблон не являются уже установленным EXL3 runtime.

Репетиция не подменяет прямой эфир. Если сервер не успевает подготовиться, честно показать, какой этап ещё идёт, а не переключаться на прогретую модель без объяснения.

## Последовательность показа

1. Выбор сервера, SSH, инвентаризация и заполнение профиля.
2. Предварительные проверки, установка runtime, загрузка закреплённых весов.
3. Полный SHA256, запуск, прогрев и реальные API-проверки.
4. Model UI, подключение клиента, Read и учебная кодовая задача.
5. Передача материалов, сохранение результатов и завершение аренды.

Подробные команды и восстановление после ошибок — в [инструкции чистой установки](11-live-cold-start.md). Этап считается завершённым по своей проверке, а не по времени. Сеть, диск и JIT влияют на длительность; сроки до чистой репетиции не обещаются.

## Демонстрация возможностей

1. **UI:** попросить объяснить короткий фрагмент кода, затем уточнить ответ. Показать раздельные reasoning/content и одну ошибку/ограничение при необходимости.
2. **Read:** клиент должен сам вызвать инструмент и прочитать контрольную строку, неизвестную модели заранее. Это уже проверено на первоначальном стенде.
3. **Coding:** [учебный invoice-проект](../examples/demo-project/README.md): сначала показать падающие тесты, затем дать клиенту исправить только функцию, выполнить тесты и показать diff. Не выдавать учебный кейс за общий coding benchmark.

Работа на русском и короткие кодовые задачи — сценарии показа, не доказательство качества во всех областях. Слово UNCENSORED в названии не означает гарантированную правильность или отсутствие любых отказов.

## Условия готовности к эфиру

- [ ] Чистая репетиция пройдена текущей редакцией скриптов без ручных незаписанных исправлений.
- [ ] Все команды воспроизведены по инструкции без устных пояснений и скрытых ручных правок.
- [ ] Зафиксированы образ/commits/manifest/profile, runtime видит все GPU целевой схемы (для FP8 — четыре).
- [ ] API, SSE, tool loop, Model UI и выбранный клиент работают.
- [ ] Быстрый профиль (CUDA graphs + DSpark) прошёл smoke на железе эфира; скорость записана с workload и версиями; baseline-профиль для отката под рукой.
- [ ] Coding-demo пройден моделью; известны исходный сбой и ожидаемый результат.
- [ ] Публичный архив не содержит персональных адресов, токенов, private configs и кэшей.
- [ ] Определены URL будущего репозитория и лицензия авторских материалов; условия upstream проверены.
- [ ] Подготовлены действия при задержке и завершении аренды.

Первоначальная ручная установка работала. Это сильная основа для репетиции, но не отметка выполнения новых пунктов выше.
